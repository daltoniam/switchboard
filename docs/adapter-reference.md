# Adapter Reference

## Conventions

### Unexported Structs, Exported Constructors
```go
type github struct { ... }           // unexported
func New() mcp.Integration { ... }   // returns interface
```

### Tool Naming
Tools are prefixed with integration name: `github_search_repos`, `datadog_search_logs`, `linear_list_issues`, `sentry_list_issues`.

### Argument Parsing
Use shared helpers from `args.go`. NEVER define local arg helpers in adapters.

**Bulk extraction** (2+ args at handler start — preferred):
```go
r := mcp.NewArgs(args)
owner := r.Str("owner")
repo := r.Str("repo")
if err := r.Err(); err != nil {
    return mcp.ErrResult(err)
}
```

**Conditional extraction** (inside if-blocks):
```go
if v, err := mcp.ArgStr(args, "project"); err != nil {
    return mcp.ErrResult(err)
} else if v != "" {
    // resolve project...
}
```

Available: `Str`, `Int`, `Int32`, `Int64`, `Float64`, `Bool`, `StrSlice`, `Map` — on both `Args` reader and as standalone `mcp.Arg*` functions. All return `(value, error)`.

**Pagination defaults** (reader only):
```go
page := r.OptInt("page", 1)
perPage := r.OptInt("per_page", 10)
```
`OptInt` returns the default when the value is missing, zero, or negative. Type coercion errors are silently ignored (returns default).

### Dispatch Map Test Parity

Every adapter with a static `dispatch` map **must** have two tests enforcing bidirectional parity between `Tools()` definitions and the `dispatch` map:

- `TestDispatchMap_AllToolsCovered` — every tool returned by `Tools()` has a handler in `dispatch`
- `TestDispatchMap_NoOrphanHandlers` — every key in `dispatch` has a corresponding `ToolDefinition`

When adding a new tool: add both the `ToolDefinition` in `tools.go` **and** the handler entry in the `dispatch` map. Tests will fail if either is missing.

Dynamic adapters without a static dispatch map (e.g. `notion` in hosted MCP mode) must instead prove routing parity with tests that every tool returned by `Tools()` is executable through the dynamic path.

### Error Handling
- Integration errors: return `&mcp.ToolResult{Data: err.Error(), IsError: true}, nil`
- Only return a non-nil Go error for truly exceptional failures
- The server layer wraps these into MCP error results

### MySQL

The native MySQL adapter uses `database/sql` and `go-sql-driver/mysql` for MySQL 8.4 LTS direct TCP, read-only access. See [mysql.md](mysql.md) for credential fields, aliases, verified TLS, least-privilege grants, SQL restrictions, tool limits, and verification commands.

### HTTP Client / SDK Pattern
Each adapter uses either a typed SDK or raw HTTP. Auth varies:
- **Jenkins (`jenkins`)**: three bounded core REST reads for one-level job discovery, recent build summaries and exact build status on plugin-restricted controllers. Preemptive Basic API-token authentication over verified HTTPS, optional PEM CA, installation-prefix preservation, exact segment-array paths, no redirects and typed allowlists before raw scripts and compaction. Dedicated account needs Overall/Read and scoped Job/Read only; tokens inherit broader effective permissions. See [Jenkins setup](jenkins.md) for permission residuals, tree-window semantics and real-container acceptance.
- **ntfy (`ntfy`)**: two bounded cached-notification reads against a fixed private topic on self-hosted v2.30.0. Dedicated role=user bearer token with upstream read-only topic ACL and deny-all default, verified HTTPS with optional PEM CA, no redirects, bounded NDJSON polling, and allowlisted output before raw scripts and compaction. Tokens retain account-level residual access outside the adapter. See [ntfy setup](ntfy.md) for least privilege, cache/truncation semantics and real-container acceptance.
- **authentik (`authentik`)**: three bounded identity/access reads on released 2026.8.3 using an API-intent bearer token owned by a dedicated non-superuser with `view_user` and `view_user_applications` grants for approved users. Verified HTTPS with optional CA, no redirects, mandatory `for_user`, typed allowlists before raw scripts, and policy-filtered pagination. See [authentik setup](authentik.md) for permissions, token residuals, response bounds and real-container acceptance.
- **Snipe-IT (`snipeit`)**: three bounded hardware inventory reads targeting v8.8.0, using a dedicated company-scoped `assets.view` PAT over verified HTTPS with optional CA. Exact tag candidates are reauthorized by ID. An allowlisted projection precedes raw scripts and compaction; assignee profiles, custom fields, notes and financial data are excluded. See [Snipe-IT setup](snipeit-setup.md) for effective permissions, residual token exposure, paging and real-container acceptance.
- **Wazuh (`wazuh`)**: three manager-only agent health reads on released 4.14.8. Dedicated scoped `agent:read` user in RBAC white mode, in-memory synchronized JWT renewal, verified HTTPS with optional PEM CA, no redirects, bounded pagination and response size. Safe projection applies before raw scripts and compaction; no indexer alerts, logs, keys, enrollment, restart or active response. See [Wazuh setup](wazuh-setup.md) for least privilege, residual credential visibility, paging and real-container acceptance.
- **Semaphore UI (`semaphoreui`)**: five metadata-only reads for one configured project on released v2.19.12. Setup and each execution require a non-admin guest identity with zero project mutation permissions. Verified HTTPS and optional custom CA, no redirects, bounded pages and responses, handler-level output allowlists before raw scripts. See [Semaphore UI setup](semaphoreui-setup.md) for token limitations, least privilege, pagination and live acceptance.
- **Argo Workflows (`argoworkflows`)**: two status-only REST reads against a fixed trusted HTTPS Argo Server and namespace, using a get/list-only service-account bearer token in client auth mode. Optional PEM CA trust, no TLS bypass or redirects. Strict output allowlisting precedes raw scripts and compaction; arbitrary failure messages, specs, parameters, artifacts and logs are excluded. Lists use bounded `limit`, opaque `cursor`, and optional `label_selector`. See [Argo Workflows setup](argoworkflows-setup.md) for least privilege, response bounds, and live acceptance.
- **GitHub**: `google/go-github/v68` typed SDK. Auth via `oauth2` token transport.
- **Forgejo**: `codeberg.org/mvdkleijn/forgejo-sdk/forgejo/v3` typed SDK (`v3.0.0`), authenticated with a personal access token. Required credentials: `base_url` (instance URL including any deployment subpath, without `/api/v1`) and `token`; environment overrides: `FORGEJO_BASE_URL`, `FORGEJO_TOKEN`. Disabled by default. The generic web UI uses the adapter's `PlainTextKeys` and `Placeholders` metadata for credential fields; no custom setup page.
  - **Scope**: 34 tools: 27 reads and 7 mutations. Covers repository search/list/get; authenticated user and organizations; issues and comments; pull requests, diffs, files, reviews, and merge; branches, commits, content, releases, and labels; plus Forgejo 16+ Actions CI/CD runs, jobs, and plaintext job logs. Start with `forgejo_list_user_repos` or `forgejo_search_repos`; issue/PR follow-ups take repository-local `number`, not global `id`. Actions follow-ups take `run_id`/`job_id` from list tools, not `run_number`.
  - **PAT permissions**: grant only the read access needed for repositories, the authenticated user, organizations, and issues used by your workflow. Check the instance's API/token settings for exact scope names and endpoint requirements; add write access only for intended mutations, not for read-only discovery or smoke tests.
  - **Pagination**: paginated tools default to `page=1`, `per_page=30`, maximum `per_page=50`. `forgejo_list_commits` with a nonempty `path` rejects `per_page`: Forgejo supplies server-sized chunks, advanced with `page`, without local slicing. Directory, issue/PR conversation-comment, and Actions job lists are unpaginated and reject `page`/`per_page`. Narrow comments by update time using `since`/`before`: nonzero whole-second RFC3339 timestamps with a timezone, no fractional seconds; `since` must precede `before`.
  - **Retries and context**: safe reads expose retryable HTTP 429/5xx failures to the server retry policy. Writes never retry automatically, including in scripts: an error can arrive after a mutation persisted (for example, failed mention processing after comment creation). Verify remote state before retrying an ambiguous outcome. Each call constructs a fresh SDK client with its request context while sharing the HTTP client, so cancellation/deadlines do not leak across calls.
  - **Response shaping**: `forgejo_get_repo` preserves `permissions.admin`, `permissions.push`, and `permissions.pull` during compaction; repository lists omit permissions. Conversation-comment bodies are fenced as literal Markdown (with collision-safe fences); `get_issue` renders ordinary Markdown, while `get_pull` retains structured JSON with its Markdown body. File contents retain encoding/base64 content; pull diffs are `{diff: string}`, not base64; Actions job logs are `{logs: string}` plaintext. File contents, pull diffs, and job logs have a 1 MiB response budget. `forgejo_list_action_runs` unwraps `workflow_runs`. Forgejo 16 accepts `workflow_id` and `ref` on the list-runs endpoint; the v3 SDK omits those fields, so the adapter forwards them as query parameters instead of filtering the current page locally. `ref` is the stored Git ref (for example `refs/heads/main`), not `prettyref`.
  - **Search verification**: discovery reads local tool metadata, not the Forgejo API. Disabled tools are hidden unless `discoverAll` is enabled, when they are marked unconfigured. Short queries such as `Forgejo repo`, `Forgejo issue`, and `Forgejo file content` cover common entry points. `Forgejo pull review` is intentionally broad: finding PRs, inspecting diffs, and submitting reviews are useful results. For existing reviews use `{"integration":"forgejo","query":"list pull reviews"}` rather than tuning ranking to force the review list above other workflow tools. `Forgejo CI run` and `Forgejo job logs` cover Actions run/job/log tools. `server/forgejo_test.go` checks the real catalog, top-3/top-5 discovery, stable ordering, and disabled visibility without upstream HTTP.
- **Datadog**: `DataDog/datadog-api-client-go/v2` typed SDK. Auth via `context.WithValue(ctx, datadog.ContextAPIKeys, ...)`. Site via `ContextServerVariables`. SDK has V1 and V2 API packages (`datadogV1`, `datadogV2`). Unstable operations (most of the Incidents API) are listed once in `unstableOperations` in `integrations/datadog/datadog.go`; add new ones there or the SDK refuses the call. Incident tools accept the UUID or the public id (`94`, `IR-94`) via `resolveIncidentID`. Status Pages (`datadog_*_status_page*`) use the stable `StatusPagesApi`; IDs are UUIDs and are validated before any request.
- **Linear**: Hand-rolled GraphQL over `net/http`. Auth via `Authorization: <api_key>` (no Bearer prefix).
- **Sentry**: Hand-rolled REST over `net/http` (no typed Go SDK for Sentry management API — `getsentry/sentry-go` is for error capture only). Auth via `Authorization: Bearer <auth_token>`. Base URL defaults to `https://sentry.io/api/0`. Organization slug configured once and injected into paths via `org(args)` helper.
- **Slack**: `slack-go/slack` typed SDK with **session token auth** (`xoxc-*` token + `xoxd-*` cookie)
  - `cookieTransport` (`http.RoundTripper`) injects `Cookie: d=<xoxd-cookie>`
  - Token priority: (1) config, (2) `~/.slack-mcp-tokens.json`, (3) Chrome disk-read (macOS)
  - Chrome extraction: LevelDB (`xoxc-*`) + encrypted SQLite cookies (`xoxd-*`, AES-128-CBC via Keychain)
  - Background refresh every 4h (`refresh.go`). Mutex-protected client (`s.getClient()`)
  - OAuth v2 flow (`oauth.go`) for web UI setup
  - For OAuth channel discovery, request `channels:read`, `groups:read`, `im:read`, `mpim:read` as appropriate; for history and replies request `channels:history`, `groups:history`, `im:history`, `mpim:history`. Apply these scopes in the hosted OAuth app configuration and re-authorize existing installations if missing. A bot must also be a member of private channels it reads; successful posting alone does not prove read access. Browser `xoxc-*` sessions require a current `d` cookie instead of OAuth grants. `slack_token_status` probes `auth.test` for `x-oauth-scopes` and reports whether the header was available; an unavailable scope list is not evidence of missing grants. Repeated pagination cursors are rejected with guidance to retry a single channel type.
- **Figma (`figma`)**: focused proxy to Figma's official hosted Streamable HTTP MCP (`https://mcp.figma.com/mcp`). OAuth uses dynamic client registration, PKCE, the `mcp:connect` scope, and RFC 8707 resource binding. Exposes only the FigJam planning workflow (`get_figjam`, `use_figma`, `generate_diagram`, `create_new_file`, `upload_assets`, `get_screenshot`, `whoami`) and injects `figma-use-figjam` into `use_figma` calls when omitted.
- **Mobbin (`mobbin`)**: proxy to Mobbin's hosted Streamable HTTP MCP (`https://api.mobbin.com/mcp`) using `remotemcp`. A static catalog of the eight upstream tools (five reads, three account writes) keeps search working before sign-in, and the dispatch map refuses upstream tools without a reviewed definition. Guided setup at `/integrations/mobbin/setup`; the authorization server (Supabase) is discovered through RFC 9728 protected resource metadata, then dynamic client registration, S256 PKCE, scope `openid`, and resource binding. Required credential: `mcp_access_token`; optional `base_url`. Sign-in also saves `mcp_refresh_token`, `mcp_token_expiry`, `mcp_client_id` and `mcp_client_secret`; `remotemcp.TokenRenewal` renews the login before each call that finds under an hour left, under `UpdateIntegrationShared` (cross-process file lock, re-read of the saved copy) because Higgsfield refresh tokens are single use. Environment overrides: `MOBBIN_MCP_ACCESS_TOKEN`, `MOBBIN_MCP_BASE_URL`. Search and collection tools return inline preview images, so their response cap is raised to 2 MiB. Tokens last about an hour and are not refreshed.
- **Render (`render`)**: proxy to Render's official hosted Streamable HTTP MCP (`https://mcp.render.com/mcp`) using `remotemcp`, authenticated with a Render API key as a bearer token. Chosen over a native REST adapter because Render runs and maintains this server, it covers services, deploys, events, logs, metrics, env vars, Postgres SQL, Key Value, Blueprints and Workflows, and API-key auth fits the credential form. A static catalog of 48 reviewed upstream tools keeps search working without a key; the dispatch map refuses anything else, and `select_workspace`/`get_selected_workspace` are excluded because they keep workspace state in a shared upstream session. The optional `workspace_id` credential is injected as `workspaceId` on workspace-scoped tools when the caller omits it. `query_render_postgres` is exposed as `render_query_postgres`. `list_deploys` and `list_events` return `JSON + "\n\n cursor: X"` upstream; the adapter rewrites them to `{items, next_cursor}`. Health calls `list_workspaces`, because the hosted server accepts any bearer token at the transport. Access mirrors Render's `destructiveHint`. Credentials: `api_key` (required), optional `workspace_id`, `base_url`. Environment overrides: `RENDER_API_KEY`, `RENDER_WORKSPACE_ID`, `RENDER_MCP_BASE_URL`. See [Render setup](render.md).
- **Higgsfield (`higgsfield`)**: hosted Streamable HTTP proxy at `https://mcp.higgsfield.ai/mcp` using `remotemcp`. Guided setup at `/integrations/higgsfield/setup` uses dynamic client registration, S256 PKCE, scopes `openid email offline_access`, and resource binding. Required credential: `mcp_access_token`; optional `base_url`. Environment overrides: `HIGGSFIELD_MCP_ACCESS_TOKEN`, `HIGGSFIELD_MCP_BASE_URL`. Unlike `notion` in hosted MCP mode, tools are a static curated allowlist (23 of ~150 upstream) with a dispatch map to upstream names; anything else is refused before the network. Generation tools are `AccessWrite` and describe the `get_cost` preflight. The hosted server returns a prose summary in `content` and the JSON in `structuredContent`, so the adapter uses `remotemcp.NewStructured` to return the JSON. Compaction specs cover `show_generations`, `list_voices`, `transactions`, and `show_plans_and_credits` (~30 KB raw).
- **Ashby (`ashby`)**: proxy to Ashby's official hosted Streamable HTTP MCP at `https://mcp.ashbyhq.com/mcp/v1` using `remotemcp.NewWithOptions` (endpoint path `/mcp/v1`, structured results preferred). Sign in with Ashby is the per-user mode: Ashby hosts and maintains the MCP server and scopes every call to the signed-in user's permissions. A static allowlist of 16 tools (12 `AccessRead`, `create_candidate`, `add_note_to_candidate`, `consider_candidate_for_job` as `AccessWrite`, `change_application_stage` as `AccessDestructive`) keeps search working before sign-in; the dispatch map refuses `submit_mcp_feedback` and any new upstream tool. Ashby does not publish input schemas, so `Tools()` merges the upstream parameters into the reviewed definitions once a background `ListTools` (canceled by `Close`, retried at most once a minute) or a health check has read them; search never waits on the network. Guided setup at `/integrations/ashby/setup`: RFC 9728 metadata at the origin names the `/mcp/v1` resource and the `https://mcp-auth.ashbyhq.com/oidc` issuer, then dynamic client registration, S256 PKCE, scopes `openid mcp offline_access`, `prompt=consent` (needed for an OIDC refresh token), and resource binding. Prerequisites: an Organization Admin enables MCP Server under Admin, Organization Setup, Opt-In Features; the user needs Elevated Access. Renewal uses `remotemcp.TokenRenewal`. Hosted credential: `mcp_access_token`; optional `base_url`. Environment overrides: `ASHBY_MCP_ACCESS_TOKEN`, `ASHBY_MCP_BASE_URL`. Hosted responses are never compacted (shapes are undocumented); `ashby_get_candidate` has a 256 KiB response cap in hosted mode.
  - **API key mode** (`api_key`, env `ASHBY_API_KEY`; optional `api_base_url`, env `ASHBY_API_BASE_URL`, default `https://api.ashbyhq.com`): one Ashby integration, two modes, exactly one active. A non-empty `api_key` selects native mode in `Configure` (closing any hosted session) and wins over `mcp_access_token`; the setup page clears the other mode's credentials on save (`POST /integrations/ashby/api-key` clears the sign-in tokens; the OAuth profile's `ClearCredentialKey` clears `api_key`). `Tools()` returns the native catalog in API key mode and the hosted allowlist otherwise (including unconfigured), so search never mixes catalogs; `Execute`, `CompactSpec`, and `MaxBytes` follow the same mode, which keeps names shared by both catalogs (`ashby_get_candidate`, `ashby_create_candidate`, `ashby_change_application_stage`) dispatching to the right backend (`TestDispatch_SharedNamesStayInTheirMode`). Transport: `POST https://api.ashbyhq.com/<endpoint>` with a JSON body, HTTP Basic auth (key as username, empty password), `Accept: application/json; version=1`. 401 means no key, 403 a wrong or deactivated key or `missing_endpoint_permission`; errors point to Admin → API Keys. HTTP 200 with `success:false` is a tool error built from `errorInfo` (code, message, request id) or an `errors` array; 429 and 5xx are retryable. The handler strips `success` and returns `{results, moreDataAvailable, nextCursor, syncToken}` (pagination keys only on paginated endpoints, null on the last page) so compaction can keep cursors. Tools are declared per domain in `native_*.go` as endpoint + snake_case argument tables (camelCase field derived, `as()` for renames such as `candidate_id` to `id`); only declared arguments are sent, because Ashby rejects unknown fields, and `limit` defaults to 25. 124 tools: 80 `AccessRead`, 37 `AccessWrite`, 7 `AccessDestructive` (job status, opening archive, application stage change, application delete, interview schedule update and cancel, candidate tag archive). Health check: `apiKey.info`. `compact.yaml` covers every native read except `get_api_key_info`, reports (positional rows), file URLs, transcripts, and email senders; it keeps identifiers, names, stages, statuses, dates, and job/application links and drops phones, social links, files, custom fields, and full user objects. Inside `results[]` a nested path keeps only its leaf, so lists keep small objects whole (`job`, `currentInterviewStage`) and `TestFieldCompactionSpecs_NoLeafCollisionsInArrays` guards collisions. Deliberately not exposed: deprecated `application.change_stage`/`change_source`; `candidate.anonymize` (irreversible erasure); multipart uploads (`candidate.uploadFile`, `uploadResume`, `applicationForm.submit`, `file.createFileUploadHandle`); webhooks; organization admin configuration writes (departments, locations, custom field definitions, interviewer pools, email templates, user interviewer settings, blocked email addresses); outbound email and sequences writes (`candidate.addEmailMessage`, `sequence.*` writes); compensation and confidentiality settings; approval definitions and offer reject/status/decided-at/approval start; `application.updateHistory`; `candidate.pushToHris`; fraud checks; batch `setValues` variants; project writes; `referral.delete`; `assessment.update` (partner callback); `version.list`. Live spec: `liveSandbox` read cases keyed on `ASHBY_LIVE_API_KEY` (skips with the reason when unset); `Provision` reads the account to learn ids.

  - **ID types in search results**: `id` = block wrapper ID (for reads); `collection_id` = collection ID (for `database_id` in write tools). Passing block ID as `database_id` causes 400.

## Gotchas

- **Arg helpers are shared** in `args.go` — NEVER create local copies. Use `mcp.NewArgs(args)` or standalone `mcp.ArgStr`/`mcp.ArgInt`/etc.
- **All adapters use dispatch maps** (`var dispatch map[string]handlerFunc`). Tool counts: GitHub ~100, AWS ~65, Datadog ~60, Linear ~60, Sentry ~55, GCP ~55, PostHog ~50, DigitalOcean ~45, Gmail ~44, Slack ~40, YNAB ~37, Postgres ~25, Notion ~24, Metabase ~22, ClickHouse ~20, Home Assistant ~17, RWX ~11, pganalyze ~3
- **Linear is the only GraphQL adapter**. `gql()` helper, entity resolution (`resolveTeamID`, `resolveIssueID`), field fragment constants (`issueFields`, `projectFields`)
- **AWS adapter uses `aws-sdk-go-v2`** — 11 typed service clients (S3, EC2, Lambda, IAM, CloudWatch, STS, ECS, SNS, SQS, DynamoDB, CloudFormation). Custom `unmarshalDynamoJSON` for DynamoDB AttributeValue marshalling. S3 `GetObject` capped at 10MB via `io.LimitReader`
- **PostHog adapter uses hand-rolled REST HTTP**. ~50 tools covering projects, feature flags, cohorts, insights, persons, groups, annotations, dashboards, actions, events, session replay (recordings plus their captured browser console logs via the `console_logs_log_entries` HogQL table), experiments, and surveys. Auth via `Authorization: Bearer <api_key>` (personal API key starting with `phx_`). Base URL defaults to `https://us.posthog.com`; configurable for EU or self-hosted. Most deletes are soft deletes (PATCH with `deleted: true`).
- **PostgreSQL adapter uses `database/sql` with `lib/pq`**. ~25 tools. Auth via `connection_string` or individual host/port/user/password/database/sslmode. Read-only queries wrapped in read-only transactions. `sanitizeIdentifier` prevents SQL injection. Handlers split across `databases.go`, `queries.go`, `management.go`
- **YNAB adapter uses hand-rolled REST HTTP**. ~25 tools covering user, budgets, accounts, categories, payees, months, transactions, and scheduled transactions. Auth via `Authorization: Bearer <api_key>` (personal access token). Base URL defaults to `https://api.ynab.com/v1`. All monetary amounts in milliunits (1000 = $1.00). `budget(args)` helper defaults `budget_id` to `"last-used"`. Rate limit: 200 requests/hour per token.
- **GCP adapter uses official `cloud.google.com/go` client libraries** — 17 typed clients (Storage, Compute Instances/Disks/Networks/Subnetworks/Firewalls, Functions, IAM via `google.golang.org/api/iam/v1`, Monitoring/AlertPolicy, Cloud Run Services/Revisions, Pub/Sub, Firestore, Logging/ConfigClient, ResourceManager Projects/Folders). Auth via Application Default Credentials or `credentials_json`. GCS `GetObject` capped at 10MB via `io.LimitReader`
- **iMessage adapter reads `~/Library/Messages/chat.db` directly** via pure-Go `modernc.org/sqlite` opened `mode=ro` + `query_only` (WAL-aware, so recent messages are visible; CGO-free releases keep working). ~94% of modern messages have an empty `text` column; the body lives in `attributedBody` (NSAttributedString typedstream) and is decoded by `typedstream.go`. Tapbacks are rows with `associated_message_type` 2000-2007 (add) / 3000-3007 (remove) and are folded into their target message's `reactions`. Timestamps are nanoseconds since 2001-01-01. Search uses a registered SQLite scalar function (`switchboard_imessage_match`) so decoding happens inside the scan. Sending shells out to `/usr/bin/osascript -` with message text passed only as argv (never interpolated), is off unless `allow_send=true`, and honors `send_allowlist`. Requires macOS Full Disk Access (read) and Automation → Messages (send); on non-macOS `Configure` fails unless `db_path` points at a copied `chat.db`.
- **`search` returns `ToolDefinition` metadata**, not raw API specs
